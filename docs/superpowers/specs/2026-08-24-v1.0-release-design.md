# AxiStream 1.0 — Release Master Plan

**Date:** 2026-08-24
**Status:** Decomposition approved; sub-project specs pending

## Problem

AxiStream at v0.1.15 is stable and well tested: 57 test files, three-platform CI with real
smoke-boot jobs, owned-OBS runtime isolation enforced by a CI gate, and a shipping
auto-updater. The core loop — capture, encode, OAuth go-live, health chips, masks,
push-to-talk, audio device pickers — is done.

What it is not yet is a *streaming application*. It is a very good go-live button. Three
gaps decide which one 1.0 ships as:

- A streamer who wants a facecam has to leave AxiStream for OBS, which forfeits the
  entire value proposition.
- There is no local recording, despite the OBS record plumbing already existing for the
  audio test.
- When something goes wrong on a user's machine, neither the user nor we can collect
  evidence. The renderer has no error boundary, so a React throw is a white window with
  no recourse. The mic-silent incident went root-cause-unpinned for exactly this reason.

Alongside those, a set of smaller gaps read as unfinished rather than broken: quality
settings are display-only prose, there is no non-fatal error channel (the only feedback
patterns are full-screen overlays and a 1.5s "Copied!"), no first-run sequencing, no
in-app version or OBS attribution surface, and one `:focus` rule in the entire stylesheet.

## Goal

Ship 1.0 as an application a Guild Wars 2 streamer can use *instead of* OBS, not in front
of it — without regressing the reliability that v0.1.x earned.

## Decomposition

Eleven items across four subsystems is too much for one spec. This is the umbrella
document; each sub-project below gets its own `docs/superpowers/specs/` design, its own
implementation plan, its own feature branch, and its own merge.

Ordering is by dependency, not by theme.

### 1. Renderer foundation

Toast system, error boundary, and the accessibility floor (`:focus-visible`, keyboard
paths for drag-only controls).

First because every sub-project downstream needs a way to report non-fatal failure, and
today there is none: `MaskEditor` plugin-install failures, Discord webhook test failures,
and updater errors currently either vanish or escalate to a full-screen overlay. Also the
first place a renderer crash stops being unrecoverable.

Deliberately small. It is foundation, not a design system.

### 2. Diagnostics export

Collect app log, owned-OBS log, scenes JSON, and encoder/device state into a zip the user
can hand us, plus the Settings entry point to produce it.

Consumes the toast channel from #1. Independent of everything else. Sequenced before the
risky feature work rather than after it, so that when #3 and #4 hit unfamiliar hardware
there is already a way to find out why.

### 3. Recording (VOD) + end-of-stream summary

Record while streaming and record without streaming, built on `RecordController` — the
lifecycle-A approach was already chosen. Ending a stream currently just stops; the summary
gives it a close: duration, average bitrate, dropped percentage, watch link, and open-VOD.

Grouped deliberately. The summary's main payoff is the open-your-recording affordance, so
splitting them means designing the summary twice.

### 4. Webcam source

A camera input composited as a scene item, with corner presets and a size control, reusing
the positioning machinery `MaskEditor` already proves out.

**Known landmine, and a required section of this spec rather than an afterthought:** the
scene-rebuild path destroys scene *items* while inputs survive. That is what silenced mic
and desktop audio on stream before `cf03496`. Any new scene-item source needs a
post-rebuild re-add.

### 5. Editable quality settings

Bitrate, output resolution, FPS, and force-software overrides layered over the existing
hardware auto-detect, which remains the default and the recommended path.

Kept separate from #6 despite both touching `SettingsScreen`: merging unrelated behaviors
into one spec because they share a screen is how specs go wrong.

### 6. Global hotkeys

Generalize the portal-shortcuts machinery push-to-talk already owns into a bindable action
registry — go live, mute, mask toggle — so the app is usable without alt-tabbing out of
the game.

### 7. Release: first-run flow, Settings/About cleanup, CHANGELOG, 1.0 bump

The guided first-run sequence (capture, YouTube, mic check, "you're ready") can only
sequence features that exist, so it genuinely has to come last. The Settings restructure
and the About panel ride along because they are the same screens.

About is not merely polish: AxiStream redistributes OBS, and `docs/obs-redistribution.md`
should be reachable from the UI rather than only from the repository.

The version bump is the release step where the updater must be proven to survive a
major-version jump, deliberately before real users are on 1.0.

## Explicitly out of scope for 1.0

- In-app YouTube live chat — large, and alt-tabbing works today.
- macOS. 1.0 is Windows + Linux, stated plainly in the release notes.
- Linux code signing.
- Multiple scenes, overlays, and transitions.
- Guild Wars 2 game-state HUD beyond the existing Mumble Link title variables.

## Conventions for every sub-project

- Design spec in `docs/superpowers/specs/`, implementation plan in
  `docs/superpowers/plans/`, feature branch, `Merge feat/x: ...` commit to main.
- Gates before merge: `npm -w @axistream/app run test`,
  `npm -w @axistream/capture run test`, and
  `cd packages/app && npx tsc --noEmit -p tsconfig.json`.
- OBS calls stay best-effort (`console.warn`, never throw out). Nothing added here may
  block boot or block go-live.
- New main-process dependencies require running the build gate — the packaged bundle is
  where they break, not the test suite.

## A note carried forward from the copy-link spec

That design specified renderer-side `navigator.clipboard`, which had to be replaced with a
main-process clipboard call in PR #12. The lesson generalizes to this whole release:
renderer-only shortcuts that work in `npm run dev` are worth re-checking against a
packaged build before a spec calls them settled.
