# 1.0 Release — First Run, About, Release Notes — Design

**Date:** 2026-08-25
**Status:** Approved
**Umbrella spec:** `docs/superpowers/specs/2026-08-24-v1.0-release-design.md` (sub-project 7)

## Problem

Sub-projects 1-6 shipped. What remains before 1.0 is the part a first-time user
meets and the part a maintainer repeats every release, and neither exists yet.

A fresh install lands on `StreamScreen`'s capture hero (`setupPhase`), picks a
display, and then arrives at the stream screen with nothing pointing at the two
things still standing between them and a watchable stream: a connected YouTube
account and a microphone that has actually been heard. Someone who hits Go Live
at that moment is stranded — the failure the guided flow exists to prevent.

The maintainer side is worse. AxiStream has no `RELEASE_NOTES.md`, no `LICENSE`,
no `THIRD_PARTY_NOTICES.md`, no Discord release announcement, and a release
workflow that publishes autogenerated notes. Every other Axi app (axivale,
axipulse, axiforge, axilog) shares one release cycle; AxiStream is the outlier.
It also redistributes a GPL-2.0-or-later OBS build while declaring no license of
its own and surfacing `docs/obs-redistribution.md` nowhere in the UI.

## Goal

Ship the first-run experience, the About panel, the house release cycle, and the
`0.1.15 -> 1.0.0` bump — with the updater proven to survive a major-version jump
before real users are on 1.0.

## Non-goals

Carried from the umbrella spec: in-app YouTube live chat; macOS (1.0 is Windows +
Linux, stated in the release notes); Linux code signing; multiple scenes,
overlays, or transitions; GW2 game-state HUD beyond the existing Mumble Link
title variables.

Also out of scope here: reconstructing release notes for the fifteen shipped
patch releases. `RELEASE_NOTES.md` starts at 1.0.

## 1. First-run state

One new persisted field in `StreamSettings`:

```
onboardedVersion: string   // '' until the wizard is finished or dismissed
```

A string rather than a boolean so a future release can re-run onboarding for a
genuinely new step without a settings migration. 1.0 only ever asks whether it is
empty.

`AppState` gains `showWelcome: boolean`, computed in main as
`onboardedVersion === ''`, so the renderer never learns the settings shape. One
new API call, `dismissWelcome()`, writes the current app version and clears the
banner permanently. Every other step of the wizard reuses calls that already
exist: `provision()`, `connectYouTube()`, `setMicDevice()`, `recordAudioTest()`.

`showWelcome` is deliberately **not** conditioned on capture being set up. Someone
who bounced off the capture picker still needs the path back.

## 2. The welcome banner

A single row at the top of the Stream screen, above the preview, rendered only
while `showWelcome`:

> New to AxiStream? A two-minute setup gets you live.  **[Set up]**  **✕**

**Set up** opens the wizard. **✕** calls `dismissWelcome()`. The banner blocks
nothing — Go Live works around it, which is the whole reason it is a banner and
not a gate.

## 3. The wizard

A modal over the app, same idiom as `TitlePromptModal`. Four steps, each with
Back / Next and a persistent **Skip setup**.

1. **Capture.** If `state.capture` is set, show a check and the source label;
   Next is enabled. If not, a *Choose what to capture* button calling
   `axi.provision()`; the step waits on `state.capture` appearing. This reuses the
   existing provisioning path rather than duplicating the picker.
2. **YouTube.** `connectYouTube()`, showing the connected channel when it lands.
   Skippable, with a line pointing at the stream-key fallback in Settings.
3. **Mic check.** The mic device picker plus the existing six-second
   `recordAudioTest()` record-and-play, so the user hears themselves before a
   stranger does.
4. **You're ready.** A recap of the three, and a **Go live** button that closes
   the wizard and leaves the user on the Stream screen.

Closing by any route — finish, Skip setup, or ✕ — calls `dismissWelcome()`.
Dismissal is never a trap: Settings -> About carries *Run setup again*.

## 4. About panel

A tenth `<section className="setting">` in `SettingsScreen`'s grid, placed last,
beside Updates — both are "about this install". The grid is CSS columns with
`break-inside: avoid`, so a tenth card costs nothing.

Contents:

- The app version, and a **Run setup again** button reopening the wizard.
- **Open source:** "AxiStream bundles OBS Studio 32.1.2, licensed
  GPL-2.0-or-later", linking to `docs/obs-redistribution.md` on GitHub and to
  `releases/latest`, where the corresponding-source archive is attached by the
  release workflow's compliance upload. This is the redistribution
  obligation the umbrella spec calls out, and it is why About is not merely
  polish.
- Links: repository, privacy policy (`PRIVACY.md` exists), report an issue.

All links go through the existing `openExternalUrl` handler.

## 5. Licensing files

Folded in here rather than deferred: AxiStream ships a GPL-linked bundle while
declaring no license of its own.

- `LICENSE` at the repo root.
- `license` field in the root and `packages/app` `package.json`.
- `THIRD_PARTY_NOTICES.md`, following the axiam / axilog pattern — OBS Studio
  first, then the notable bundled dependencies.

The About panel links to both.

## 6. Release cycle

The umbrella spec says "CHANGELOG"; the house convention across every sibling Axi
repo is `RELEASE_NOTES.md`, and the house convention wins.

- **`RELEASE_NOTES.md`** at the repo root. Sections headed
  `## Version vX.Y.Z — Month D, YYYY`, written as user-facing prose with feature
  headlines — what changed and what it means, not a commit dump. The 1.0 section
  states Windows + Linux, and that macOS is not in 1.0.
- **`release.yml` gains a *Publish release notes* step** that extracts the
  section matching the pushed tag and PATCHes it as the GitHub Release body,
  **failing loudly when no section exists for that tag**. It runs *before* the
  OBS compliance upload — v0.1.12 stuck as a draft because a later step died
  before `--draft=false`, and a notes gate placed after the uploads would
  reproduce that failure shape exactly.
- **`scripts/post-discord-release.mjs`**, ported from axivale: reads the same
  `RELEASE_NOTES.md` section, posts an embed via the bot token, invoked from the
  workflow with the release channel ID.

This closes a loop that already half-exists: `getWhatsNew()` reads GitHub release
bodies, so writing `RELEASE_NOTES.md` is what makes the in-app What's New panel
say something worth reading.

## 7. The 1.0.0 bump

`packages/app/package.json` `0.1.15 -> 1.0.0`, last, on its own commit.

Doing it deliberately is the point: the major digit has never moved, and both
`selectReleaseNotes`'s version parsing and the electron-updater feed compare
versions. Verification is a real one, not a unit test — install 0.1.15, publish
1.0.0, confirm the running app offers and applies the update. The failure mode
lives in the packaged artifact, which is where new main-process behaviour always
breaks first.

## Testing

- `first-run.test.tsx` — banner visibility against `showWelcome`, and that ✕
  calls `dismissWelcome()`.
- `welcome-wizard.test.tsx` — one test per step driving the mocked `axi`, in the
  shape of the existing `settings-screen.test.tsx`; plus that every exit route
  dismisses.
- `about-settings.test.tsx` — the OBS attribution text and that each link calls
  `openExternalUrl` with the right URL.
- Main-side: `onboardedVersion` defaulting and round-tripping through
  `StreamSettings`, and `showWelcome` derivation.
- Release-notes extraction gets a shell-level check against a fixture, including
  the missing-section failure.
- Existing gates apply: `npm -w @axistream/app run test`,
  `npm -w @axistream/capture run test`, and
  `cd packages/app && npx tsc --noEmit -p tsconfig.json`.

## Risks

The updater major-jump is the one irreversible step — a 1.0.0 that existing
0.1.15 installs cannot see would strand every current user on a dead version.
It is verified against a real install before the tag is announced.

The Discord announcement and the notes gate both touch the release workflow,
which is only exercised on a real tag. Both are written to fail loudly rather
than publish something wrong.
