# 1.0 Release — First Run, About, Release Cycle — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship AxiStream's first-run flow, About panel, licensing files, and the house release cycle, then bump 0.1.15 → 1.0.0 with the updater proven across the major-version jump.

**Architecture:** One new persisted settings field (`onboardedVersion`) surfaces to the renderer as a derived `AppState.showWelcome` boolean; a dismissible banner and a four-step modal wizard both live in the renderer and reuse existing IPC calls rather than adding new ones (the only new call is `dismissWelcome()`). The About panel is a tenth flat card in the existing settings grid. The release cycle follows the sibling Axi repos: a hand-written `RELEASE_NOTES.md` whose per-tag section becomes the GitHub Release body via a workflow step that fails loudly when the section is missing.

**Tech Stack:** Electron 31, React 18, TypeScript (ESM/NodeNext), vitest + @testing-library/react, electron-builder, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-08-25-v1.0-release-design.md`

## Global Constraints

- Code style: 2-space indent, **no semicolons**, single quotes, named exports, `.js` extensions on relative imports. No linter is configured — match surrounding code.
- Tests: `npm -w @axistream/app run test` and `npm -w @axistream/capture run test` (vitest, fork pool capped at 2). Never raise the worker cap.
- Typecheck gate: `cd packages/app && npx tsc --noEmit -p tsconfig.json`.
- OBS calls are best-effort (`console.warn`, never throw out) — nothing OBS-side may block boot or go-live.
- New IPC calls must be added in **four** places, in this order: `CH` map and `AxiApi` interface in `packages/app/src/shared/state.ts`, the `AxiHandlers` interface + `ipcMain.handle` line in `packages/app/src/main/ipc.ts`, the bridge in `packages/app/src/preload/index.ts`, and the handler implementation in `packages/app/src/main/index.ts`. Missing any one fails typecheck or silently no-ops at runtime.
- Repository is `github.com/darkharasho/axistream`. Docs site is `stream.axi.link` (GitHub Pages from `docs/`).
- Bundled OBS Studio version is **32.1.2**, licensed **GPL-2.0-or-later**.
- Release notes file is `RELEASE_NOTES.md` (house convention), **not** `CHANGELOG.md`. Section heading format is exactly `## Version vX.Y.Z — Month D, YYYY` (em dash).
- 1.0 ships **Windows + Linux**. macOS is not in 1.0 and the release notes say so.

```tsx
import { useEffect, useRef, useState } from 'react'
import { Check, Loader2, X } from 'lucide-react'
import type { AppState, AudioDevice, AxiApi } from '../../shared/state.js'
import { useModalKeys } from '../use-modal-keys.js'

const STEPS = ['Capture', 'YouTube', 'Microphone', 'Ready'] as const

export function WelcomeWizard({ state, axi, onClose }: { state: AppState; axi: AxiApi; onClose: () => void }) {
  const [step, setStep] = useState(0)
  const ref = useRef<HTMLDivElement>(null)
  useModalKeys(ref, onClose)

  const [devices, setDevices] = useState<AudioDevice[]>([])
  const [test, setTest] = useState<{ st: 'idle' | 'recording' | 'ready' | 'error'; url?: string; error?: string }>({ st: 'idle' })
  useEffect(() => { void axi.getAudioDevices().then(setDevices).catch(() => setDevices([])) }, [])

  const capture = state.capture
  const connected = state.youtube.connected

  // Only the capture step gates. YouTube and the mic check are skippable —
  // a stream key set later in Settings is a legitimate path, and a user who
  // knows their mic works should not have to prove it.
  const canAdvance = step !== 0 || capture !== null

  const runMicTest = async () => {
    setTest({ st: 'recording' })
    const r = await axi.recordAudioTest()
    if (r.ok && r.clip) setTest({ st: 'ready', url: URL.createObjectURL(new Blob([r.clip], { type: r.mime ?? 'audio/mp4' })) })
    else setTest({ st: 'error', error: r.error ?? 'Test failed' })
  }

  return (
    <div className="modal-backdrop">
      <div className="modal wizard" ref={ref} role="dialog" aria-modal="true" aria-label="Set up AxiStream">
        <div className="wizard-head">
          <h3>{STEPS[step]}</h3>
          <button className="welcome-x" aria-label="Close" onClick={onClose}><X size={13} /></button>
        </div>
        <ol className="wizard-dots">
          {STEPS.map((s, i) => <li key={s} className={i === step ? 'on' : i < step ? 'done' : ''} />)}
        </ol>

        {step === 0 ? (
          <div className="wizard-body">
            <p className="muted">AxiStream captures one screen or window — the one showing your game.</p>
            {capture
              ? <p className="wizard-ok"><Check size={14} /> Capturing {capture.sourceLabel}</p>
              : <button className="btn primary sm" onClick={() => void axi.provision()}>Choose what to capture</button>}
          </div>
        ) : null}

        {step === 1 ? (
          <div className="wizard-body">
            <p className="muted">Connecting YouTube lets AxiStream create the broadcast for you — no stream key to copy.</p>
            {connected
              ? <p className="wizard-ok"><Check size={14} /> Connected as {state.youtube.channel}</p>
              : <button className="btn primary sm" onClick={() => void axi.connectYouTube()}>Connect YouTube</button>}
            <p className="muted">You can skip this and paste a stream key in Settings instead.</p>
          </div>
        ) : null}

        {step === 2 ? (
          <div className="wizard-body">
            <p className="muted">Hear yourself before a stranger does.</p>

- [ ] **Step 3: Write the extractor**

Create `scripts/release-notes.mjs`:

```js
// Extract one `## Version vX.Y.Z — <date>` section out of RELEASE_NOTES.md.
// The release workflow uses this as the GitHub Release body and treats a
// missing section as a hard failure, so a release can never go out with
// autogenerated notes.
//
//   node scripts/release-notes.mjs vX.Y.Z
import { readFile } from 'node:fs/promises'
import { fileURLToPath } from 'node:url'
import { dirname, join } from 'node:path'

const root = join(dirname(fileURLToPath(import.meta.url)), '..')

/** @param {string} md @param {string} tag @returns {string} */
export function extractNotes(md, tag) {
  const out = []
  let capturing = false
  for (const line of md.split('\n')) {
    const header = line.match(/^## Version (v\S+)/)
    if (header) {
      if (capturing) break
      if (header[1] === tag) capturing = true
      continue
    }
    if (capturing) out.push(line)
  }
  return out.join('\n').trim()
}

// Only run the CLI when invoked directly, so the self-test can import the
// function without triggering a process.exit.
if (process.argv[1] && process.argv[1].endsWith('release-notes.mjs')) {
  const tag = process.argv[2]
  if (!tag) {
    console.error('usage: node scripts/release-notes.mjs vX.Y.Z')
    process.exit(1)
  }
  const md = await readFile(join(root, 'RELEASE_NOTES.md'), 'utf8')
  const notes = extractNotes(md, tag)
  if (!notes) {
    console.error(`No RELEASE_NOTES.md section found for ${tag}. Add a '## Version ${tag} — <date>' entry and re-run.`)
    process.exit(1)
  }
  process.stdout.write(notes + '\n')
}
```

## Before you tag

**Write the `RELEASE_NOTES.md` section first**, as `## Version vX.Y.Z — Month D, YYYY`.
The `publish` job reads the GitHub Release body out of it and fails when the section
is missing, so skipping this does not degrade the notes — it fails the release.

Write for the person running the app, not for the commit log: what changed, and what
it means for them. Every other Axi app's notes read this way.

Check it before pushing:

```sh
node scripts/release-notes.mjs vX.Y.Z
```

## Cutting a release

1. Bump `packages/app/package.json`'s `version` and commit it. (The build jobs also
   sync the version from the tag, but the committed value is what a dev build and the
   About panel report.)
2. Add the `RELEASE_NOTES.md` section and commit it.
3. Tag and push:

   ```sh
   git push origin main
   git tag vX.Y.Z && git push origin vX.Y.Z
   ```

4. Watch the run. The jobs are: `test` → `build` (Linux + Windows) and `build-mac`
   (signed + notarized) → `publish`.

`publish`, in order: sets the release body from `RELEASE_NOTES.md` (**fails here if the
section is missing**), uploads the OBS corresponding-source compliance assets, flips the
release out of draft, then announces to Discord if `DISCORD_RELEASE_CHANNEL_ID` is set.

The notes step is deliberately first. In v0.1.12 a later step died before
`--draft=false` ran and the release stayed invisible as a draft — anything that can fail
belongs before the release becomes public, not after.

## Secrets and variables

- `DISCORD_BOT_TOKEN` (secret) and `DISCORD_RELEASE_CHANNEL_ID` (variable) — the
  announcement. Absent, the release still publishes and the step is skipped.
- Mac signing: `CSC_LINK`, `CSC_KEY_PASSWORD`, `APPLE_ID`,
  `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_TEAM_ID`.
- YouTube OAuth, baked into the bundle at build time: `AXI_YT_CLIENT_ID`,
  `AXI_YT_CLIENT_SECRET`. These must be stored **unquoted** — quoted values were
  baked in literally once and produced "OAuth client not found" at runtime.

## Task 8: The 1.0.0 bump

**Files:**
- Modify: `packages/app/package.json`

**Interfaces:**
- Consumes: `RELEASE_NOTES.md`'s v1.0.0 section (Task 6), the notes gate (Task 7).
- Produces: nothing code-facing.

This task ends in a **manual verification that a subagent cannot complete alone**. Do steps 1-4, then stop and hand step 5 to the user with the exact instructions below. Do not tag or push.

- [ ] **Step 1: Bump the version**

```bash
npm version 1.0.0 --no-git-tag-version --allow-same-version -w @axistream/app
```

Confirm: `grep '"version"' packages/app/package.json` shows `1.0.0`. The root `package.json` stays at `0.0.0` — it is a private workspace root and is never published.

- [ ] **Step 2: Confirm the notes section matches the version**

Run: `node scripts/release-notes.mjs v1.0.0`
Expected: the 1.0.0 body prints. If it fails, the tag and the notes disagree and the release would die in `publish` — fix `RELEASE_NOTES.md` before going further.

- [ ] **Step 3: Run every gate**

```bash
npm -w @axistream/app run test
npm -w @axistream/capture run test
cd packages/app && npx tsc --noEmit -p tsconfig.json && cd ../..
npm run build
```

Expected: all pass. `npm run build` matters here specifically — the About panel and wizard are new renderer code and the packaged bundle is where new code breaks, not the test suite.

- [ ] **Step 4: Commit**

```bash
git add packages/app/package.json
git commit -m "chore: bump version to 1.0.0

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>"
```

- [ ] **Step 5: Hand the updater verification to the user**

The major digit has never moved in AxiStream's history. Both `selectReleaseNotes`'s version parsing and the electron-updater feed compare versions, and a 1.0.0 that existing 0.1.15 installs cannot see would strand every current user on a dead version. This is the one irreversible step in the plan and it cannot be unit-tested — the failure lives in the packaged artifact.

Report to the user, verbatim:

> The 1.0.0 bump is committed but **not tagged**. Before tagging, the updater needs to be proven across the major-version jump:
>
> 1. Install the released **0.1.15** artifact (AppImage or deb) and run it.
> 2. Push the `v1.0.0` tag and let the release workflow finish — confirm the release leaves draft with the `RELEASE_NOTES.md` body, not autogenerated notes.
> 3. In the still-running 0.1.15 install, hit Settings → Updates → **Check for updates**. It must offer 1.0.0, download it, and apply it on restart.
> 4. Confirm the What's New panel shows the 1.0.0 notes afterwards.
>
> If step 3 does not offer the update, do not announce 1.0 — that is the strand-every-user failure, and it is fixable only before people upgrade.

Do not tag, push, or announce on the user's behalf.
